# Intent-shadow candidate 0.1 — deterministic core and frozen live protocol

Laboratory-only implementation of point 5. Production remains read-only and
no model call, service control or GPU inference has been made. The original
offline core remains separate from a prepared, fail-closed live runner.

The implementation keeps four phases separate:

1. `intent_shadow_extract.py` strictly decodes raw model JSON;
2. `intent_shadow_normalize.py` derives only position IDs, unique ports,
   omitted empty outcomes and hashes;
3. `intent_shadow_validate.py` validates the three exclusive roots, data
   dominance, barrier ownership and continuations without reading a query;
4. `intent_shadow_evaluate.py` opens the canonical gold only after a complete
   saved batch has passed query-only identity checks.

The evaluator reproduces every saved extraction from its raw bytes before it
opens gold. It publishes separate columns for technical/document validity,
root, full semantic equality, operation graph, route, data edges, barrier
ownership, system control and typed unrepresentability.

The model contract is generated by `intent_shadow_projection.py` exclusively
from the frozen registry. There are no surface-language triggers, query
exceptions, special route rewrites or embedded gold. The current registry
naturally yields `undo_last_turn` and `get/approval`; a synthetic-registry test
renames both and proves that projector and validator follow registry data.

Panels remain distinct under Roberto's approved option A:

- 120 canonical cases, typed by the intent-shadow oracle;
- 4 typed intent-shadow controls;
- 34 legacy focus/binding controls, frozen in `legacy_panel_v0_1.json` and
  evaluated only by their Phase-1 oracle. They are not converted or
  compensated with either typed panel.

`intent_shadow_runner.py` remains dry/fake-only. The separately frozen
`live_runner.py` is the sole network-capable path and refuses execution unless
a new `live_run_authorization_v0_1.json` binds an independent audit and final
root authorization to the exact protocol/freezes. That file is intentionally
absent. Offline preflight cannot open a socket.

The verifier and preflight expose two explicit states. `disarmed` requires no
authorization; `armed` requires exactly the selected hash-bound authorization.
Authorization is not a run artifact. Consumption, journal, checkpoint,
partial/sealed batches and evaluation output remain blocking evidence of a
started run. The offline armed command is `live_runner.py --preflight-armed`.

The single-measurement protocol fixes 158 queries for both arms (316 POSTs):

- arm A is the current `runtime.intent_extractor.extract_intent` with current
  v4 prompt, read-only detection lexicon, and a frozen registry adapter;
- arm B is the candidate's direct intent-shadow schema/prompt;
- even `sample_index` uses AB and odd indices BA;
- both use llama.cpp build 1422 (`e3546c794`), Qwen3.6-35B-A3B Q4_K_M,
  temperature 0, seed 42, 4000 output tokens, thinking off, 120 seconds,
  and zero retry;
- 120 canonical, 4 typed controls and 34 separate Phase-1 cases are reported
  independently. No cross-panel compensation is permitted.

The control snapshot pins exact repo sources, the logical detection-lexicon
contents, backend binary, service configuration and the 22.6 GB weights hash.
Because the approved protocol permits exactly one request per arm/case, a
deterministic current bypass still receives one paired model request, while
the optional current SITE/ELSEWHERE second probe is disabled after the primary
response. The adapter records this explicit delta.

The live parser limits are fixed at 256 KiB, depth 64, 10000 nodes, 64 KiB per
string and 64 integer digits. Exceeding one is always `technical_invalid`,
never semantic `unrepresentable`.

After independent audit and a separate final authorization, the only planned
