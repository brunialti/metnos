Documento interno - bench scalability prefilter

Stress test su pool di 84 (catalog reale), 250, 500, 1000 tool (catalog reale + distractor sintetici da combinazioni verb x object x provider hypothetic). 300 query per pool size, deterministico (no LLM).

Verdetto: il punto di caduta NON e' visibile fino a 1000 tool. Il vocabolario chiuso §2.2 + canonical verb/object detection sopprime il rumore dei distractor. Recall@5 degrada solo -5.7 pp tra pool 84 e 1000 per le strategy token-based (token_flat_v2, selective_semantic, cached_token_flat).

Confronto letteratura: ToolBench/ToolLLM (Qin et al. 2024) mostra recall crollo 50-70% tra 50 e 500 tool su corpora REST eterogenei. Metnos -5.7 pp tra 84 e 1000 = ordine di grandezza migliore.

Implicazioni: - Headroom di scaling enorme: estrapolando, recall <50% solo a pool

5000 tool. - Roberto puo' crescere a 50-100 skill senza re-architecture. - token_flat_v2 confermato come default in produzione.

Lettura

  • Recall@5 robusto a scaling: strategy che mantengono recall stabile al crescere del pool sono adatte per produzione futura (oltre 100 skill).
  • Latency slowdown < 2x desiderabile fino a pool 500.
  • Strategy con filter deterministico (verb_first, constraint, trie) dovrebbero scalare meglio del token-flat puro.
