Frontier di responsabilità

Metnos gestisce direttamente il proprio runtime + storage + config (database sqlite, indices foto/text, log turn, credentials cifrate, manifest executor, cache rigenerabile).

Delega a supra tutto ciò che è infrastruttura ML condivisa potenzialmente riusabile da altri client: embedder BGE-M3 ONNX, geocoder Photon/Nominatim, STT/TTS, voice backend, Python venv comune. La separazione permette ad altre applicazioni (oggi solo Metnos, domani altri agenti) di consumare gli stessi servizi senza duplicare modelli.

Delega a host il livello sistema operativo (driver GPU Vulkan, systemd LLM serving, sudo policy NOPASSWD limitata) e modelli di grandi dimensioni (Gemma 4 26B GGUF, whisper.cpp).

Usa SaaS solo per capability che non hanno senso self-host: LLM frontier (Anthropic Opus/Sonnet/Haiku + OpenAI GPT-5 fallback) come quality ceiling sopra Gemma locale; Cloudflare per CDN+tunnel; provider opzionali (Google Workspace, GitHub) per skill che si interfacciano a servizi cloud altrui.

Implicazioni operative

  • Backup priority: solo ~/.local/share/metnos/{credentials,index,scheduler_v2.sqlite,persons.sqlite,users.sqlite,turns} + ~/.config/metnos/. Cache rigenerabile, supra ripristinabile da repo.
  • Self-hosted footprint: ~700 MB Metnos storage (index foto domina con 487 MB) + 589 MB supra venv + ~30 GB modelli (Gemma 4 26B + Qwen2-VL + Whisper) sul host.
  • Single point of failure: GPU Vulkan driver host. Se cade, llama-server + whisper-server giù → Metnos resta vivo ma degradato (solo frontier SaaS, niente local middle/wise).
  • Costi mensili stimati: SaaS frontier ~$15-30/mese se uso modesto consult_frontier; Cloudflare gratis; provider skill (Google/GitHub) gratis con account personale; Anthropic/OpenAI variable in base a query volume.
