# Metnos MIT licensing update

## Owner request and scope

The owner explicitly requested that Metnos use the MIT license. The previous
first-party license was AGPL-3.0. The authoring Git history attributes the
project commits to Roberto Brunialti (including his GitHub identity).

The root `LICENSE` now contains the standard MIT text and the notice
`Copyright (c) 2026 Roberto Brunialti`. This change covers Metnos first-party
source and documentation, not third-party dependencies, companion services
or downloaded model weights. Their licenses and notices are not changed.
The README makes that boundary explicit. Historical published revisions are
not rewritten, and the earlier distribution ADR retains its original text
with an English note identifying the licensing decision as superseded.

## Updated surfaces

- Root license and README badge/explanation.
- Both first-party Rust package license fields.
- First-party SPDX headers, including builtin source mirrors and tests.
- Installer startup banner and English/Italian disclaimer/catalog strings.
- English/Italian website entry pages, code notes and Quick Tour HTML/PDF.
- Derived builtin manifests, reviewed source pins and source inventory via
  the normal release preparation command; no gate or signature bypass.

## Verification

An AST comparison of all 124 initially changed Python files proves identical
program structure, allowing only the requested AGPL-to-MIT string replacement
in the installer disclaimer and language catalog. The later source-review
pin and builtin metadata changes are generated by the established procedure.

The focused suite passes **18 tests**: license consistency, installer
documentation contracts and public Quick Tour/PDF publication. The PDF check
normalizes glyph-extraction whitespace (Chromium may yield `M IT`) and proves
the language-specific license footer. Both PDFs were regenerated from their
HTML masters. Published-document validation passes for 99 HTML documents in
English and Italian. The export's current license, README, installer and
website sources contain no stale AGPL claim.

No installation test or production restart was performed as part of this
licensing-only change. The separate cold-install acceptance is scheduled for
2026-09-16 01:00 Europe/Rome. It will use the public GitHub revision available
then, including this licensing update. The running release and its Tutor
catalog remain unchanged until a separately verified runtime release.
