Organizzare i file

organize_files organizza file locali con un piano mostrato prima delle modifiche, consenso esplicito, ricevuta e undo.

Organizzare non significa soltanto spostare

Spostare significa portare file già scelti in una destinazione già indicata. Organizzare significa applicare una regola a un insieme preciso: per esempio eliminare copie identiche dalla sorgente e distribuire i file rimanenti in base alla data o al progetto. Ordinare una lista di risultati, invece, non cambia i file.

Indica le cartelle da trattare, se includere le sottocartelle, le eventuali cartelle di confronto e le destinazioni. I riferimenti usati soltanto per il confronto non vengono modificati. Un nome uguale o una foto somigliante non bastano per decidere che due file sono duplicati: si confronta il contenuto completo.

Prima il piano, poi la decisione

  1. Completa la richiesta nel form. Se mancano informazioni, Metnos le chiede con un modulo. Anche scelte e consenso passano da form: nella chat web oppure tramite il collegamento al modulo ricevuto su Telegram. Un semplice «sì» scritto in chat non sostituisce la conferma.
  2. Esamina il piano completo. La preview non sposta e non cancella i tuoi file. Il piano distingue spostamenti, copie duplicate da rimuovere, file lasciati al loro posto e problemi da risolvere. Riporta le destinazioni e gli eventuali nomi alternativi. Un riepilogo abbreviato deve dichiararlo: non equivale alla consultazione di tutte le azioni.
  3. Autorizza soltanto effetti reali. Se il piano non prevede alcuna modifica, la preview termina senza chiedere autorizzazione. Se invece prevede spostamenti o rimozioni, puoi confermare o annullare nel form. La conferma vale soltanto per quel piano, che rimane congelato.
  4. Leggi la ricevuta. Dopo il consenso Metnos applica esattamente le azioni approvate, senza ricalcolare altre destinazioni o aggiungere file. La ricevuta documenta ciò che è realmente avvenuto, compresi eventuali problemi: una preview non è una ricevuta di lavoro eseguito.
  5. Annulla, se necessario. L'undo usa la ricevuta per ripristinare gli spostamenti e le copie rimosse. Prima verifica che il ripristino sia ancora sicuro; non sovrascrive un file cambiato nel frattempo. Ripetere un annullamento già concluso non ripete gli effetti.

Piani lunghi. Il modulo può mostrare un riepilogo limitato, dichiarato come tale. Il consenso resta legato all'intero piano congelato: un riepilogo abbreviato non equivale alla consultazione di tutte le azioni.

Come formulare la richiesta

Questi esempi mostrano come delimitare sorgenti, riferimenti e regole; non sono trascrizioni di operazioni già eseguite.

Organizza le foto nella cartella «Da organizzare» sul server Metnos, senza entrare nelle sottocartelle. Confrontale con «Archivio foto»: rimuovi dalla sorgente soltanto le copie identiche già presenti nell'archivio e distribuisci le altre per anno e mese di scatto. Mostrami prima il piano.

Le due cartelle devono essere distinte. La cartella sorgente delimita dove si possono rimuovere duplicati; l'archivio è il riferimento da conservare. Se una data manca, la destinazione non va inventata: si definisce nel form se lasciare il file dov'è oppure fermare il piano.

Trova i documenti nella cartella «Da archiviare» sul server Metnos, estrai il progetto dal contenuto e organizza quei risultati nelle cartelle di progetto già esistenti. Prima mostrami il piano.

Qui ricerca, estrazione e organizzazione appartengono alla stessa richiesta. La regola usa il campo project estratto, non inventa un progetto dal nome del file. Non dare per scontato che «questi file» richiami i risultati di una richiesta precedente già conclusa: indica di nuovo l'ambito.

Se un nome è già occupato

Non si sovrascrive il file esistente. La regola può fermare il piano oppure proporre un nome con un suffisso ricavato dal contenuto. Anche quando due file in ingresso avrebbero lo stesso nome, il nome finale deve comparire nella preview. Questa scelta non autorizza a eliminare il file già presente.

Limiti della prima versione

  • File locali sul server Linux di Metnos: non file di un PC Windows collegato, dispositivi remoti o archivi cloud.
  • Spostamenti sullo stesso filesystem: il passaggio a un altro disco o filesystem non è supportato.
  • Cartelle sorgenti e destinazioni già esistenti, comprese le sottocartelle finali. Le destinazioni devono stare fuori dalle cartelle sorgenti: questa versione non crea automaticamente la struttura anno/mese.
  • Percorsi senza collegamenti simbolici. Le rimozioni di duplicati con collegamenti fisici multipli non sono ammesse.

Se i file cambiano dopo la preview

Se un file o una cartella non corrisponde più a quanto verificato, oppure una destinazione viene occupata, Metnos rifiuta di proseguire con quel piano. Occorre una nuova preview e, se ci sono effetti reali, un nuovo consenso. Non adatta silenziosamente il piano già approvato.

Se un problema sopraggiunge durante l'applicazione, Metnos tenta di ripristinare le operazioni già compiute e ne conserva l'esito nella ricevuta. Anche il ripristino può essere impedito da cambiamenti esterni: controlla l'esito, senza presumere che tutti i file siano tornati al loro posto. L'undo non sostituisce un backup indipendente.
