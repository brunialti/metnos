1. How to read this page

Metnos is more than a chat window: it can find, read, transform and create content, use configured services, operate on paired devices and run scheduled tasks. This page brings those capabilities together without confusing what is available with what remains an architectural possibility.

A capability is considered available only when it has an executor or active service, an input and output contract, applicable policies, and an authorisation path. Ideas without those elements are explicitly identified as unavailable. The current operational list is also available in web chat under Settings › System › Services.

2. Capabilities beyond chat

A. Local files, documents and indexes

Metnos can work on authorised server paths and, when requested, on paired devices. Operations include:

  • finding files and directories, listing folders and retrieving metadata;
  • computing hashes and signatures, comparing content and finding duplicates;
  • reading text, PDFs, documents, CSV files, spreadsheets and images through OCR;
  • creating or updating documents and spreadsheets, converting formats, compressing, moving and sharing files;
  • building and querying local image indexes, including temporal and geographic metadata when present.

Search does not grant automatic access to the whole filesystem: every path remains subject to workspace policy and the user's identity.

B. Services, accounts and other systems

Configured accounts extend available operations without changing the authorisation model. Depending on active services, Metnos can:

  • find, read, send, reply to, label or move messages;
  • consult contacts, people, calendars and events, and create or update permitted items;
  • find and manage images in Google Photos;
  • use authenticated websites through a controlled browser session;
  • run local operations on paired Windows or Linux computers.

Additional mailboxes and accounts can be used by entering their credentials. Credentials belong to the user who configured them and do not make data, sessions or authorisations shared.

C. What Metnos does not observe autonomously

Metnos currently provides no ambient voice listening, home-automation control, passive observation of third-party chats, or general agent-to-agent channel. It does not monitor a family conversation in the background or infer assignments from sources the user has not queried or authorised. An external agent cannot approve operations on a user's behalf.

These possibilities may be studied as future extensions, but they require verifiable identity, consent from the people involved, constrained sources and a dedicated audit contract. They are neither hidden options nor capabilities that can be enabled by a simple setting.

D. Proposals and controlled initiative

Metnos can formulate proposals when the producing subsystem has a mandate and relevant data, for example by suggesting the next step after a search or showing a change before applying it. A proposal is not an authorisation: operations with external effects still pass through policy, the vaglio and approval.

Scheduled tasks are a separate case. The user creates a mandate with a date or recurrence; the scheduler runs it in the same user's context and records its result, errors and next run. This is not spontaneous initiative by the model.

E. The web, places and external content

External capabilities include:

  • web search and collection of relevant URLs;
  • reading HTML pages and PDFs, and finding images on the web;
  • finding places, resolving geographic names and coordinates, and retrieving location information;
  • navigating and interacting with sites through the controlled browser, including sessions that require credentials;
  • using configured Google services while keeping accounts and authorisations isolated per user.

Web content remains untrusted data: it cannot change policy, grant permissions or issue privileged runtime instructions.

F. Telos and the vaglio

Telos express declared ends and preferences. The vaglio separates evaluation from proposal and applies constitutional constraints before any utility judgement. A user profile may guide the final wording of a response, but it does not covertly alter deterministic routing or turn model-generated prose into evidence.

When personal information is used, the reliable source remains the authorised original turn or datum. The relevant user must be able to inspect, correct and delete preferences and observations.

3. Users, devices and sessions

Every operation runs in a user's context. Language, preferences, credentials, services, sessions, scheduled tasks and data are not transferred to another user merely because they share the same server.

A paired device is an execution location, not a second identity. When the same person moves from a phone to a computer, they can continue the earlier session by transferring it to the current device; alternatively, they can make the current session active and close the earlier one, or cancel. The choice affects that user only.

4. Invariant constraints

  • Human authority: no service or external agent approves operations on a user's behalf.
  • Least privilege: executors, browsers and remote devices receive only the mandate required for the current step.
  • Per-user isolation: co-location on one instance does not make data and credentials shared.
  • Traceability: requests, approvals, executions and errors produce inspectable events.
  • Revocability: their owner can revoke or delete sessions, credentials, tasks and personal data.
  • Source boundary: web pages, documents and model output are content to assess, not privileged instructions.

5. Natural-language examples

Ask Metnos with requests such as these:

  • “On my Windows laptop, find PDFs modified this week and show me the ones with identical hashes.”
  • “Read expenses.xlsx, group amounts by category and create a new sheet with the summary.”
  • “Search the web for the official instructions to renew an identity card in Bologna, and give me sources and their update dates.”
  • “Find pharmacies open near Piazza Maggiore and show their addresses and distances.”
  • “Using my work account, find messages from Marta from the last seven days that have PDF attachments.”
  • “In my personal calendar, create ‘Eye examination’ on Tuesday at 16:00; show me the details before confirming.”
  • “Open the courier's website, use my credentials and check shipment 12345.”
  • “Every Monday at 08:00, check the following seven days of appointments and send me a private summary.”

If the request comes from Telegram and refers to a settings page, the stated path is in the Metnos instance's web chat.
