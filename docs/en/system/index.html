System overview

The System section presents the components that an administrator can inspect or configure through the web interface. It does not catalogue every internal detail: it explains the purpose of each page, the actions it permits, and the checks required after a change.

Inspect before acting

The administration pages keep several easily confused conditions separate. A process may be running without being healthy; a component may be healthy while one of its functions remains deliberately inactive; a capability may be installed but disabled. Likewise, pairing a channel or device does not automatically grant every action. Identity, autonomy, policy, and executor authority remain separate controls.

A dependable change always follows the same sequence: read the effective state, choose an action from the closed catalog, wait for the system to converge, then check health and desired state again. The interface does not expose a generic shell and does not turn arbitrary values into system commands.

Administrative access. These pages may contain operational configuration and user data. Open them only through a trusted administrator session. The public documentation contains neither secrets nor personal values.

Finding your way around the web interface

  1. System navigation. Direct links to the six areas covered in this section.
  2. Overview. Summarises the number of installed and running services and shows the refresh interval.
  3. Component card. Separates process state, application health, and desired state.
  4. Feature and process kept separate. The LRE worker can be healthy while the feature remains deliberately disabled.
  5. Bounded actions. The interface displays only actions admitted for that service and its current state.
