03 TYPES, ORIGINS AND COSTS

How it works.
Where it comes from.

The brain identifies the executor type, not the number of model calls. A step may take a path that uses no model. All three icons appear in the real case.

DET · Deterministic

Runs rules and code. That step does not use a model; preparing the plan may still use one.

LLM · Model assisted

Can use a language model for part of the work, such as presenting or transforming data.

AGENT · Internal decisions

Observes, chooses and acts through multiple steps within an assigned mandate and limits. It may stop before reaching the outcome.

Origin answers a different question

The executor list also shows where a component comes from. Origin, model use and execution location are separate properties.

handcrafted

Written and maintained in the project.

synthesized

Generated with a model and admitted into the system. This does not imply a model call on every run.

imported

Derived from an external skill, with recorded provenance and admission into the system.

builtin

A service built into the runtime. Some are available to the planner; others are restricted.

$ means cloud, not a price

The $ symbol, when present, indicates cloud model calls reported by an executor. It does not appear in this case. It is not a price, and its absence does not make the entire turn free: the planner may also use a model. Consult Monitor for recorded call measurements.

04 USERS AND DEVICES

Your user account.
On your devices, too.

Metnos can pair one or more computers with a user and run executors on those devices. The target computer needs the Metnos client.

  1. 1
    Pair the device with a user

    In Settings → System → Devices, the administrator selects the owner and gives the computer a name.

  2. 2
    Open the link on that computer

    The guided process installs the Metnos client and establishes a verifiable identity. The initial link expires after a limited time.

  3. 3
    Run compatible executors there

    The server sends authorised, signed requests. The client verifies the component, runs it and returns the result.

Close to your files, within granted permissions. Reachability alone is not enough: compatibility, resources and authorisation also matter. An administrator can revoke the device.

How do I mount a NAS folder in Metnos?

A mount makes a NAS share accessible as a local folder without copying its files. On Linux, Metnos can prepare an SMB/CIFS mount when the administrative operation is available and authorised.

“Mount //storage.example.org/Photos in Metnos’s Pictures folder, read-only.”

The address and share are examples. The folder must be accessible to the service account. If credentials are needed, use the protected password field. If the NAS is already accessible, reuse the existing path.

Persistence after a restart requires separate configuration: a successful mount does not guarantee it. Check by listing the files. Connecting a folder does not index it: the first photo search may start preparation in the background. The Tutor explains the procedure but does not mount anything.
