## Context

Once the three-tier LLM architecture (ADR 0025) was settled, the
fallback rule for unconfigured tiers needed a precise definition.
The default proposal — alias an unconfigured tier to a lower one
(`wise → middle → fast`) — turned out to be dangerous for the wise
tier specifically.

The synt's `generate` stages (specification, skeleton, birth-test)
are the points where Metnos *decides how new pieces of itself are
born*. The quality of the generated executor determines the quality
of the pool for months afterward. Silently degrading those stages to
`qwen3:8b` (which had already failed `extract_email_addresses` by
producing empty `python_code`, see ADR 0025) would synthesize
sub-quality executors and the user would see no error — only a slow
accumulation of bad code that the synt would propose for approval.

The empirical evidence from 26 April was unambiguous: `qwen3:8b`
fills the structural fields of a tool-call but leaves `python_code`
blank, regardless of prompt hints. It is structurally below the
floor, not just a configuration choice. Gemma 4 26B (probed the same
day, 38.7s for 1794 output tokens, AST OK, smoke OK on
`analyze_text_statistics`) is at or above the floor. Claude
Sonnet 4.6 / Opus 4.7, GPT-4 family, Gemini Pro are at or above the
floor.

## Decision

The wise tier has a quality floor; below it, runtime fails at boot.

**Whitelist (above floor).** Local models at "Gemma 4 level" or
better — Gemma 4 26B+ (A4B Q4_K_M and equivalent), Gemma 3 27B+,
Qwen 3 32B+, Llama 4 family — and any of the major frontier online
providers (Anthropic, OpenAI, Google, Mistral). Implemented as
`WISE_QUALITY_WHITELIST_*` in `runtime/llm_router.py`.

**Resolver rules** (replacing the generic alias-down rule of ADR
0025 for the wise case):
- `fast` missing → boot error. The fast tier is the safety net; it
  must always exist.
- `middle` missing → alias **upward** to `wise` (same concrete
  model). Not downward to `fast`.
- `wise` missing → boot error. Never silently degrades to `fast`.

The unified reason: degrading `synt.generate` (or any other
high-tier component) to `qwen3:8b` silently means synthesizing
sub-quality executors or judging with an undersized model. An
explicit configuration error is preferable to invisible degradation.

**User consequence.** A user with modest hardware *must* configure
an external provider for the wise tier (and therefore for the middle
tier, which aliases up). The default for "users without Roberto's
hardware" becomes
`wise = anthropic:claude-sonnet-4-6` with `ANTHROPIC_API_KEY` in the
environment. Roberto's local default is `wise =
llamacpp:gemma-4-26B-A4B-it-UD-Q4_K_M` on `:8080`.

**Failure UX.** When `wise` is unavailable at runtime (provider
unreachable, budget exhausted, model not present), the synt's
`generate` returns a graceful error to the channel: "I cannot
generate new executors in this configuration." This is the explicit
form of the non-renunciation telos (ADR 0010): the system tells the
user what it cannot do, instead of producing a degraded result that
looks like success.

The decision pairs with `LlamaCppProvider` and `AnthropicProvider`
becoming first-class providers, not stubs.

## Alternatives considered

**Allow wise to degrade to fast with a warning.** Pro: no boot
error. Con: a silently degraded synt produces sub-quality executors
that the user approves under the false belief they were generated by
a wise model; the technical debt accumulates invisibly. Rejected.

**Whitelist by model name (regex on `model_id`) only.** Pro: simple,
machine-checkable. Con: a model name is not a guarantee of capability
(quantization level, fine-tune variants, etc.). Mitigation: the
whitelist also accepts external providers (whose default models are
known to clear the floor) and includes a small set of known-good
local models. The full safety check is a smoke test at boot if
configured, not an inferred guarantee. Adopted.

**Skip the floor; let the user configure anything.** Pro: maximum
flexibility. Con: the most common misconfiguration in the indie
context — "use the cheapest model everywhere" — corrupts the synt
silently. The system has to defend against this. Rejected.

## Consequences

The runtime's bootstrap is more verbose: it has to validate the
configured wise model against the whitelist or smoke-test a chat
call before declaring readiness. The cost is real (a few extra
seconds at boot) and is the right place to spend it.

For Roberto's setup, the wise tier is local Gemma 4 26B; for
documentation aimed at "other users" the example configuration uses
Anthropic. The doc `synt.html` chapter 4.2 ("Generare") states the
rule explicitly: stages 2/3/5 require an LLM at Gemma 4 26B level or
above. If not available locally, configure an external provider.

The executor diary (ADR 0030) records, for each born executor, the
wise tier used and the concrete model. This is forensic data: when a
particular executor underperforms, the model that produced it is
visible.

The interaction with ADR 0044 (default fast = `qwen3:8b`) is
deliberate: fast is the safety net, configured by default, available
on any machine. Wise carries the quality floor, configurable by the
user, *required* if synth is to be used. Middle aliases up to wise
when missing, so configuring wise correctly handles two of three
tiers.
